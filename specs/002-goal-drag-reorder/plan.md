# Implementation Plan: Goal Drag-and-Drop Reordering

**Branch**: `002-goal-drag-reorder` | **Date**: 2026-05-12 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `specs/002-goal-drag-reorder/spec.md`

## Summary

Add manual drag-and-drop reordering to the active goals list. Users grab a goal by its grip handle and drop it above or below any other active goal; the new order is immediately reflected in the UI and written to localStorage. Implemented using `@dnd-kit/sortable` (React 19-compatible) with Tailwind CSS for all visual feedback. Completed goals are not draggable. Keyboard reordering is out of scope (deferred).

## Component Architecture

### SortableGoalList

Wraps the active goal list with dnd-kit context. Handles the complete drag lifecycle.

```
SortableGoalList
  └─ DndContext (sensors: PointerSensor + KeyboardSensor disabled, onDragEnd)
       └─ SortableContext (items: activeGoalIds, strategy: verticalListSortingStrategy)
            └─ SortableGoalCard × N   (each wraps GoalCard with useSortable)
       └─ DragOverlay
            └─ GoalCard (ghost, rendered at pointer position during drag)
```

### SortableGoalCard (internal to SortableGoalList)

Thin wrapper that calls `useSortable(goal.id)` and passes `dragHandleProps` (attributes + listeners) down to `GoalCard`.

### GoalCard (modified)

Receives optional `dragHandleProps`. When present, renders `DragHandle` with those props as the leftmost element. The rest of the card (checkbox, title, badge, delete button) is unchanged.

### DragHandle

```tsx
<button {...dragHandleProps} aria-label="Drag to reorder" className="...touch-target...">
  <GripVertical className="h-4 w-4 text-muted-foreground" />
</button>
```

## Data Flow

```
User drops goal
  → onDragEnd (DndContext)
      → arrayMove(activeGoals, oldIndex, newIndex)
      → reorderGoals(newOrderedIds)          [useGoals hook]
          → rebuild goals array with normalized sortOrder (0, 1, 2, …)
          → saveGoals(updated)               [storage.ts]
              → localStorage.setItem(...)
              → on QuotaExceededError: set storageError state
          → setGoals(updated)
```

## Visual Feedback Design

| State | Visual |
|---|---|
| Idle | Grip handle visible on left of each active card (muted colour) |
| Hover over handle | Cursor changes to `grab` |
| Dragging | Dragged card becomes semi-transparent in place; `DragOverlay` shows full-opacity ghost at pointer |
| Over target | Target card gains a 2px coloured top border (insertion line above) using Tailwind `border-t-2 border-accent` via `isOver` state |
| Drop complete | Ghost disappears; list re-renders in new order instantly |
| Cancel (Escape/outside) | Ghost disappears; list reverts to pre-drag order |
| Save error | Inline error banner appears below active goals list |

## Backward Compatibility

Existing localStorage data (goals without `sortOrder`) is migrated transparently in `loadGoals()` using `migrateGoals()`. No data is lost; the existing creation-time order is preserved as the initial manual order. The migration is written to storage on the next user action.
